# Лабораторная работа 3

## Цель

Настроить хранилище секретов для сервиса предсказания качества вина, убрать зависимость приложения от локальных secret-файлов и обеспечить получение DB credentials через Vault.

## Что сделано

1. В проект добавлен отдельный контейнер `vault` на базе `hashicorp/vault`.
2. В `docker/vault/start-dev-vault.sh` реализован автозапуск Vault в dev-режиме и автоматическое заполнение секрета `secret/wine-quality/database`.
3. В приложение добавлен модуль `src/wine_quality_mlops/vault.py`, который получает секреты через HTTP API Vault.
4. В `src/wine_quality_mlops/database.py` реализована сборка строки подключения к БД на основе секрета из Vault.
5. В `src/wine_quality_mlops/app.py` добавлены DB-backed endpoints:
   - `/training-data/summary`
   - `/predictions/latest`
   - `/predict` с сохранением результата в БД
6. В `src/wine_quality_mlops/seed.py` и `scripts/seed_database.py` добавлена загрузка train/test данных в PostgreSQL.
7. В `docker-compose.yml` добавлены сервисы `postgres`, `vault`, `api`, `db-seed`.
8. Локальные `.env` и другие отдельные secret-файлы для приложения не используются: `api` и `db-seed` получают только адрес Vault, token и путь секрета.
9. Для Jenkins добавлены repo-defined pipeline файлы `jenkins/lab3-ci.Jenkinsfile` и `jenkins/lab3-cd.Jenkinsfile`.

## Поток секретов

1. Контейнер `vault` стартует и создает секрет `secret/wine-quality/database`.
2. Контейнер `api` получает только `VAULT_ADDR`, `VAULT_TOKEN`, `VAULT_SECRET_PATH`.
3. При инициализации `PredictionStore` приложение вызывает Vault API и получает:
   - `DATABASE_HOST`
   - `DATABASE_PORT`
   - `DATABASE_NAME`
   - `DATABASE_USER`
   - `DATABASE_PASSWORD`
4. После этого строится SQLAlchemy connection string и приложение подключается к PostgreSQL.

## Команды запуска

```powershell
docker compose up -d --build postgres vault api
docker compose --profile seed run --rm db-seed
Invoke-RestMethod http://127.0.0.1:8000/health
python tests/functional/run_scenario.py --scenario scenario_lab3.json --base-url http://127.0.0.1:8000 --report functional-test-report.json
docker compose exec vault vault kv get secret/wine-quality/database
docker compose down -v
```

## Результат

- Секреты авторизации БД перенесены в Vault.
- Приложение получает креды при обращении к БД через Vault client.
- Хранение предсказаний и датасета работает через PostgreSQL.
- Реализация совместима с локальным запуском без БД: если Vault и БД не настроены, базовый `/predict` остается доступен.

## Проверка

Проверка была выполнена на локальном compose-стенде `postgres + vault + api`.

- `db-seed` успешно загрузил `1087` train-records и `272` test-records.
- Функциональный сценарий `scenario_lab3.json` завершился со статусом `passed`.
- `/health` вернул `database_status = { enabled: true, connected: true }`.
- `/predict` сохранил предсказание в БД и вернул `stored_in_db = true`.
- `/predictions/latest` вернул только что сохраненную запись с `prediction_id = 1`.
- Vault CLI подтвердил наличие секрета `secret/data/wine-quality/database` с полями `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_DRIVER`.

## Jenkins

Для Jenkins подготовлены два pipeline job:

- CI job со script path `jenkins/lab3-ci.Jenkinsfile`
- CD job со script path `jenkins/lab3-cd.Jenkinsfile`

CI pipeline собирает и проверяет проект на Windows Jenkins node через PowerShell, а CD pipeline поднимает Lab3 compose-стенд и повторно валидирует его функциональным сценарием.

## Примечание для защиты

Используется учебный dev-режим Vault с локальным token `root`. Это сделано специально для лабораторной, чтобы стенд собирался автоматически и воспроизводимо без ручной инициализации.
